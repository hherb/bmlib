# Record lookup by identifier — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Part 1 — a caller's `html` source no longer ends `FullTextService`'s chain. Part 2 — `lookup_record()` returns one paper's `FetchedRecord` from a PMID, DOI, PMC ID or PPR accession, Python and Rust.

**Architecture:** Part 1 changes Tier 0 in `bmlib/fulltext/service.py` and `rust/bmlib/src/fulltext/service.rs` to hold an `html` entry and use it as the last-resort link. Part 2 adds `bmlib/publications/lookup.py` and `rust/bmlib/src/publications/lookup.rs`, which ask Europe PMC (PPR only), OpenAlex (always) and PubMed (when a PMID is known) through the injected HTTP client, reusing the existing PubMed and OpenAlex parsers, and a new Europe PMC normaliser. A committed fixture generated by Python is replayed by Rust.

**Tech Stack:** Python 3.11+ (httpx-style injected client, `xml.etree`), Rust (`HttpClient`, `roxmltree`, `serde_json`), pytest, cargo test.

**Spec:** `docs/superpowers/specs/2026-10-30-record-lookup-design.md`

## Review Focus

1. **A PubMed body carrying its `<!DOCTYPE … PUBLIC "-//NLM//DTD …">` prologue** (every live efetch does): Rust must parse it (`parse_ncbi_xml`, `allow_dtd`). Every PubMed body in the fixture carries the DOCTYPE — Task 7.
2. **A DOI holding `?`, `#` or a space**: the OpenAlex path must still name that DOI and not truncate at the `?`. The id is percent-encoded with `/` and `:` kept literal — test in Task 5, fixture case in Task 7.
3. **Mixed-case input**: `pmc7745181`, `ppr1325930`, `DOI:10.1056/NEJMoa2034577` all canonicalise; a PubMed DOI in registered case still matches an OpenAlex DOI in lower case when detecting a preprint — Task 5.
4. **Non-ASCII digits** (`PMC١٢٣`, a PMID `١٢٣`) are refused before any request in both languages; Rust's `normalise_pmc_id` accepts them (#564), so the Rust lookup checks ASCII itself — Tasks 5 and 8.
5. **An OpenAlex 200 whose `ids.pmid` is absent and whose DOI differs from the one asked** is `other_record`, and no PubMed request follows — Task 5.

**Files:**

**Interfaces:**
- Produces:
  ```python
  class SourceOutcome(StrEnum): FOUND, NOT_FOUND, REQUEST_FAILED, UNREADABLE, OTHER_RECORD, BOOK_RECORD, NOT_ASKED  # wire names per Global Constraints
  @dataclass(frozen=True) class SourceReport: outcome: SourceOutcome; message: str
  @dataclass(frozen=True) class PublishedVersion: pmid: str | None; doi: str | None; pmc_id: str | None
  @dataclass(frozen=True) class RecordLookup:
      record: FetchedRecord | None; published_version: PublishedVersion | None
      pubmed: SourceReport; openalex: SourceReport; europepmc: SourceReport
      def to_dict(self) -> dict[str, Any]; @classmethod def from_dict(cls, data) -> RecordLookup  # refuses a record to_dict did not write (ValueError)
  def lookup_record(client: Any, *, pmid: str | None = None, doi: str | None = None,
                    pmc_id: str | None = None, ppr_id: str | None = None, email: str,
                    ncbi_api_key: str | None = None, openalex_api_key: str | None = None) -> RecordLookup
  ```
  `FetchedRecord.to_dict()` keys are the dataclass fields in order, nested entries through their own `to_dict`; `from_dict` the inverse.
- Requests (exact): Europe PMC `GET {EUROPEPMC_REST_BASE}/search`, params `{"query": f"EXT_ID:{ppr} AND SRC:PPR", "resultType": "core", "format": "json"}`; OpenAlex `GET https://api.openalex.org/works/{key}` with `key` one of `pmid:{pmid}`, `pmcid:{PMC…}`, `doi:{quote(doi, safe="/:")}`, params `{"mailto": email}` plus `"api_key"` if given; PubMed `GET pubmed.EFETCH_URL`, params `{"db": "pubmed", "id": pmid, "retmode": "xml"}` plus `"api_key"` if given. Order: Europe PMC, OpenAlex, PubMed.
