# Roadmap

This document tracks planned and implemented features for bmlib, grouped by
theme. Details of finished work stay brief — git history and `docs/plans/`
hold the full story.

| Status | Feature | Details |

| ✅ Done | Consolidate JSON extraction | Issue #17 — one locator, `iter_json_spans()`, yields candidate spans in six priority stages without validating; `extract_json()` and `extract_and_repair_json()` are acceptance policies over it, dropping ~70 lines of duplicated fence and brace scanning. A fenced candidate outranks the object preference, and the repair path suppresses the nested-object stage so it cannot return a fragment of a span it rejected (0.6.0) |
| ✅ Done | A whole span beats a nested fragment | Issue #33 — `extract_json()` reduced an unfenced array of objects to its first element, dropping every sibling with no error, on a path both the Anthropic and OpenAI-compatible providers run for every `json_mode` response. The acceptance policy is now `_first_acceptable()`, run twice: whole spans first, the nested-object stage only when nothing at the top level parsed. Its non-dict fallback is *ranked* — a list holding an object beats any other non-dict span — because first-parseable would let an incidental `[]` be accepted by the first walk and substitute unrelated data that parses cleanly. `extract_and_repair_json()` gets no second walk: repairing a fragment fabricates structure the model never emitted. The same preference applies one layer up: `parse_json()` asks for whole spans only (`allow_fragments=False`), tries repair, and re-asks with fragments allowed only if repair also failed — a *truncated* array of objects never balances, so taking the fragment there dropped the sibling and skipped the repair that recovers the whole array (0.6.0) |
| ✅ Done | Field-level JSON salvage | `salvage_json_fields()` — when a long structured response is malformed in one place, recover the fields that are intact instead of losing all of it. Generalises biasbuster's `lenient_extract`; at most one repair pass per key, at the last match (0.6.0) |

| ✅ Done | `parse_json`'s return contract | Issue #33 — annotated `dict \| list`, which is what it always returned, and *enforced*: a bare scalar response now raises rather than slipping past an annotation that excludes it. Plus an opt-in `require_dict` that raises in `parse_json()` and retries inside `chat_json()` (fail-fast at temperature 0, mirroring truncation). `@overload` on `Literal[True]` keeps a real `dict` for strict callers, with a third `bool` variant so a runtime flag still type-checks. | ✅ Done *(unreleased)* | The full text scanned is the article's own | Issue #119, found reviewing PR #118 — `TransparencyAnalyzer` never consumes `JATSParser` output: it fetches `fullTextXML` itself and regexes the raw string, so every `<sub-article>`/`<response>` region was scanned as the article's. Reviewers write in exactly the vocabulary these scans hunt for, and a round's *"the reviewers declare no competing interests"* became this paper's disclosure, its data statement this paper's data level, and an *"employee of"* line an industry tie the paper never disclosed. Removed in `_fetch_europepmc_fulltext()`, the one door the full text enters through.
